Rethinking Structured Generation: Can Graph-Based Reasoning Resolve Ambiguity?

Can a model produce more reliable structured outputs by considering multiple plausible interpretations instead of assuming only one answer is correct?

Ratun Rahman & Atit PokharelNeurIPS 2026 · AcceptedLLMs / NLP / Graph Reasoning

Research problem

Many structured-generation systems map a natural language input to exactly one target structure. Real language does not always work that way: two distinct structures may be semantically valid for the same underspecified request. Training solely against one reference risks suppressing alternatives and producing unstable outputs.

Approach

We frame structured generation as ambiguity-aware inference rather than single-output prediction. The method creates a set of plausible outputs, expresses each as a graph of entities and relationships, and reasons across these candidates using semantic alignment and relational consistency. It is designed to compare competing interpretations beyond token-level likelihood.

What the evaluation examines

  • Accuracy on structured generation benchmarks
  • Output stability when input wording or ambiguity changes
  • Robustness when more than one interpretation is defensible

The paper reports exact-match, robustness, ambiguity-stratified, and candidate-level analyses. The controlled ablation below isolates the contribution of graph scoring and multi-valid supervision.

Publication status: Accepted to NeurIPS 2026. This project description is a readable summary of the published abstract and is not a substitute for the full paper.

How the method works

01Generate candidate structures

Retain plausible SQL or visualization outputs instead of collapsing immediately to one prediction.

02Convert to relational graphs

Use task-specific nodes and edge types for fields, operations, entities, and their relationships.

03Score with an edge-aware GNN

Two message-passing layers and graph-level pooling inform semantic, structural, and relational scoring.

04Use multi-valid supervision

Preserve alternative valid outputs during training when validity checks are available.

Conceptual workflow redrawn for this portfolio. See the full paper for the formal objective, implementation details and complete experiments.

Limitations and scope

Task-specific graph construction is needed for each structured-output schema. Multi-valid training assumes valid alternatives can be reliably identified; a single-reference graph scorer is also possible. Additional candidate generation and GNN-based selection introduce computational cost, and the published analysis should not be interpreted as a benchmark of deployment latency.
